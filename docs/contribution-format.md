# 给大肥鱼添一份知识：BV 投稿格式 v1

大肥鱼主服务器的知识库查询服务**免费使用**。默认插件自动领取并保存安装 ID，无需邮箱、MAC 或手填 ID；知识查询每 ID 与每来源 IP 各滚动 60 秒最多 5 次。可选邮箱账号保留且不自动绑定安装 ID。贡献完全自愿，不是免费调用的前提。机器人自身模型、视频观看工具及第三方 API 的费用由各自运行环境决定。

**当前状态：已开放接收待审。** 2026-10-29 已部署，首次收件由当前已安装 Harness 的官方插件运行时、现有凭据完成，未经过桌面 GUI 或模型选工具。随后已在真实桌面 GUI 新会话中由模型调用投稿与本人状态查询：同一材料幂等复投返回 `duplicate:true`，保持同一贡献编号、内容哈希与原等待时钟，仍为 `pending_review`。材料继承既有 Bot 的视频来源记录，两次验证都没有重新观看视频或生成新事实。真实自然 24 小时、独立管理员批准及真实已审内容发布仍未观察；至少等满服务器接收后的 24 小时，且由独立管理员在服务主机本地 CLI 明确批准，才允许发布，绝不到期自动批准。2026-10-26 版仅提供格式与人工审阅方案，当时“在线投稿未开放”的结论保留为历史。知识搜索和原采集管理员接口不接收投稿，也不需要向投稿入口提供管理员 Bearer 凭据。

## 提交什么

每份 JSON 对应一个原视频的一个分 P。必填内容为格式版本、原视频 BV、简短梗概和梗概来源方式。普通用户和 DSH 机器人使用同一种格式。可以附上标题、标签，以及有把握的时间点，帮助维护者核验。

写视频实际讲了什么、发生了什么、适合什么观看需求；不要只写“某位 UP 主的互动”或“很有意思”。不需要提供 UP 主姓名。提交原视频 BV，不把几小时录播或多视频汇总的 BV 当成其中某个原视频。

建议用 **100–250 字**写清具体内容、过程与结果，必要时说明笑点或梗；只写材料支持的事实，不补造结局、人物反应、梗出处或播放量。当前新加坡 Bot 的正式采集产物含 overview 和真实 segments 等字段，本投稿格式只提取贡献者能可靠提供的内容，**不要求机器人为了模仿 Bot 产物而虚构分段或时间点**。原热点 H 的选题年龄、时长和 15 天清理规则属于原采集分区，DSH 投稿暂不自动按视频年龄淘汰，也不自动套用 H 的 15 天 TTL。

最小格式如下。**这里的 BV 和内容是合成格式示例，不代表真实视频或真实观看记录；投稿时必须替换为自己实际了解的视频与内容。**

```json
{
  "schema_version": 1,
  "bvid": "BV1234567890",
  "summary": "【格式示例】视频用纸球和灯光演示月相变化，解释不同观测位置为什么会看到不同形状的月亮，适合想看轻松天文入门的人。",
  "provenance": {
    "contributor_type": "bot",
    "basis": "video"
  }
}
```

带可选信息的[完整示例](contribution.example.json)和[JSON Schema](contribution.schema.json)可直接下载。JSON 使用双引号，不包含注释或尾逗号。示例仅用于检验格式，不能原样入库。

## 字段约定

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `schema_version` | 是 | 固定为整数 `1` |
| `bvid` | 是 | `BV` 加 10 位英文字母或数字，只填编号，不填链接 |
| `summary` | 是 | 至少 12 个可见字符，原始长度最多 5000 字符；空白不凑字数，用自己的话写同一原视频、同一 P 的梗概 |
| `provenance.contributor_type` | 是 | `human` 为人工贡献，`bot` 为机器人贡献；这是自报来源，不是审核结论 |
| `provenance.basis` | 是 | `video`：实际观看；`subtitles`：依据字幕；`video_description`：只依据视频简介。只读简介不能冒称完整观看 |
| `page` | 否 | 分 P 编号，整数 1–1000，省略表示第 1 P；一份投稿不混合多个分 P |
| `title` | 否 | 原视频标题，1–300 字符；未知可省略，审核时回读原视频核对 |
| `tags` | 否 | 最多 12 个不重复标签，每个 1–40 字符，描述主题而非引流对象 |
| `highlights` | 否 | 最多 40 个时间点，全部属于本份投稿的同一个分 P |
| `highlights[].at_seconds` | 有时间点时必填 | 从该 P 开头起算的整数秒数，范围 0–2147483647；不确定就省略整条时间点 |
| `highlights[].point` | 有时间点时必填 | 该时间点的内容或观察，1–1000 字符；概述不能伪装成逐字台词 |

未知标题、时长、发布时间和时间点不要补造。时间点是否落在实际片长内，由后续核验处理；Schema 只能检查结构，不能证明事实正确。当前格式不要求用户自行提供时长、发布日期或抓取视频接口，减少错误元数据。

不接受格式外字段。已核 ID、来源 IP、贡献编号、服务器时间、内容哈希、审核状态、向量和索引路径由服务端取得或生成，不接受自报 `approved`、`review`、`account_id`、`ip` 等。正文也不要放 Cookie、验证码、安装 key、调用 ID、API Key、私密日志或签名媒体 URL；正文指令不能改变工具或审核权限。

内容 JSON 的 UTF-8 编码上限为 **32 KiB**，MCP 消息 envelope 总上限为 64 KiB。服务端以 `normalize_payload` 为统一校验入口，规范化 Unicode、换行、首尾空白与标签/时间点顺序；不合格字段或可识别的凭据、邮箱、签名 URL、显式执行指令会以固定错误码拒绝，不把匹配原文回显。该确定性初筛不能自动证明来源真实、事实准确或不存在一切注入，仍需独立审阅。

## 从 DSH 或 REST 提交

服务根为 `https://livecompanion.duckdns.org/dafeiyu`。

| 操作 | REST | MCP 工具 |
| --- | --- | --- |
| 提交内容 | `POST /v1/contributions`，请求体为上述 v1 JSON | `dafeiyu_submit_video` |
| 查看本人投稿状态 | `GET /v1/contributions/{contribution_id}` | `dafeiyu_contribution_status` |

REST 与 MCP 仍须有效的 `X-Dafeiyu-ID`，官方插件自动在 HTTP 层携带。工具参数只放投稿内容或贡献编号，不重复传 ID/IP；普通 DSH 用户不能审核或批准投稿。

`dafeiyu_submit_video` 直接接收上述 v1 字段，不套 `contribution:{...}` 外层；`dafeiyu_contribution_status` 只接收 `{"contribution_id":"DFC-<32位小写十六进制>"}`。首次收件 REST 返回 `202`，同一已核 ID、BV、P、规范化内容的幂等重复返回 `200`，不会因重复新建投稿或重置原等待时钟。

提交回执含 `contribution_id`、`status`、`payload_sha256`、`received_at`、`eligible_at`、`duplicate`。状态回执含前五项和 `reviewed_at`、`published_at`、`rejection_reason`（不含 `duplicate`）；时间为整数 Unix 秒，尚无审核或发布时对应时间可为空。状态为 `pending_review`、`approved`、`published` 或 `rejected`。普通回执不返回完整 ID、来源 IP 或投稿正文。

在当前 Harness 新会话中，明确要求“调用大肥鱼投稿工具提交以下 JSON”，附自己实际掌握的 v1 内容。查看工具回执，保存贡献编号，再要求“用大肥鱼投稿状态工具查询这个贡献编号”。工具尚未发现时先重连 MCP 让其重新发现，不能以搜索调用或直接 REST 脚本冒充 Harness 已提交。插件 0.3.1 无需修改 JavaScript 即可发现服务端新增工具；是否实际加载与提交成功须看工具和服务端回执。

当前实施默认写入额度为**每 ID 滚动 24 小时 10 次、每来源 IP 滚动 24 小时 30 次**，这组数值是本版实施选择，非用户指定。查看投稿状态不扣知识查询额度；原知识请求仍是每 ID 与每 IP 各滚动 60 秒 5 次。超限遵守 `429` / `Retry-After`，不循环重试。

## 怎样从投稿变成共享知识

以下为本版实现的双门流程，部署与自然 24 小时验证状态另看实际回执：

1. **独立收件**：合法内容持久保存到独立待审区后返回贡献编号与 `pending_review` 回执，只说明已接收，不代表视频已核实、审核通过或可检索。有效安装 ID 用于投稿认证，来源 IP 由服务端取得。
2. **校验与去重**：校验格式后，先将省略的 `page` 归一为 `1`，再按 BV＋分 P 定位视频，规范化内容哈希识别重复。Schema 的 `default` 只是声明，不会自动补字段。相同 BV 的不同梗概作为修订待审，不能因 BV 已存在就静默丢弃，也不能直接覆盖旧摘要。
3. **核对来源**：审核者核对原 BV、标题与分 P，并结合视频、字幕、时间点核验梗概；可使用既有工具辅助，但收件服务不因此声称已自动观看或核验。来源只是简介时保留其局限，不提升成已看完整视频的结论。虚构 BV、录播代替原视频或无法支持的内容应退回修订，并给出原因。
4. **等待与独立审核**：以服务器接收时钟为准，接收后至少 `86400` 秒才允许审核批准。客户端不能回填日期，重启和重试不能缩短门槛。**满 24 小时不会自动批准**；独立管理员阅读原始材料后，CLI 还须明确确认 `source_checked`（已核来源）、`content_supported`（内容有材料支持）、`original_video`（是原视频）、`no_secrets`（无私密凭据）、`no_instructions`（无执行指令）全部为 true，并匹配确定内容的哈希。普通 DSH、投稿者和正文不能自批。修改内容是新的待审修订，不沿用旧批准。自然时间未跨越时，合成时钟检查不能当作已真实等满 24 小时。
5. **隔离后发布**：待审 SQLite 不加入任何可检索索引。只有满足等待门槛并明确 `approved`，才允许写入独立 DSH 分区，成功后才是 `published`。证据不足、不合规则或被拒内容不发布；不能将 `verified:false` 标签当作隔离。此流程不因一次投稿自动启动采集 Bot、下载视频、执行正文指令或调用付费模型。原 `collector intake` 的管理员认证和仅接收元数据契约保持。
6. **按编号回查**：以贡献编号查询本人状态和审核/发布结果。HTTP 成功、Schema 通过、`pending_review` 收件和审核批准，都不能提前称为“已可检索”；只有成功发布到正式 DSH 索引后才是已入库。

请只提交可公开分享的原创梗概和事实性摘要，保留原视频 BV 来源，不复制大段字幕或私密材料。第三方视频权利不因投稿而转移。独立五项审核确认的实际命令由管理员操作说明定义，普通用户没有审核入口。

## DSH 独立知识分区

所有 DSH 发布视频统一进入 `/var/lib/dafeiyu-kb/rag/dsh_videos.json`，在 LiCO 索引目录之外；LiCO 默认不加载、不扫描、不检索本分区，不能先放进 LiCO 的 `guides_*.json` 再按标签过滤。这样避免增加 LiCO 默认索引范围；共享 CPU 或磁盘竞争对实际墙钟延迟的影响仍需另测，不能保证完全无影响。

多 P 内容审核后按 BV 聚合，明确保留 P 号与各自 `basis`；未审核 P 不混入已发布摘要，不让后一 P 静默顶替前一 P。DSH 分区与原采集产物、人物、梗、热点等既有库分开。Schema 可先用于本地结构校验，不联网、不调用模型，也不自动入库。
